# Payment architecture
- WalletTopUp never mounts gateway settings or card-token setup; Super Admin payments mounts only Grow configuration, with legacy Z-Credit UI and endpoints removed. Grow top-up orders snapshot the authorized wallet owner and deposit amount separately from subscriptions; verified atomic completion credits that wallet once before the existing SMS dispatch. Why: one gateway without exposed settings, wrong-wallet deposits or duplicate credits.
- Grow uses environment-specific secret Make webhooks, independent provider readback and a service-only atomic completion RPC; checkout redirects never prove payment. Why: no forged or duplicated entitlements.
- Grow subscription terms are snapshotted per self-owned order; sandbox never activates live entitlements or changes wallet credits. Make connection OTP stays in Make; admin fields are configuration, not credentials. Why: no invented terms or credential exposure.
- Make declares enabled checkout methods/customer fields; card, wallet and bank fields stay on hosted Grow checkout. Why: no invented support or sensitive card collection.
- Method preparation forms remain browsable without capabilities, but checkout stays disabled until the provider declares support; brand artwork uses immutable asset pointers. Why: honest preparation without fake verification or card collection.
- Wallet package tiers share a pure preview helper and DB-authoritative immutable insert snapshots; verified completion credits paid amount plus snapshotted bonus once, while old orders keep zero bonus. Why: no forged package amounts, retroactive grants or duplicate rewards.
- Verified live payment changes atomically enqueue platform-sender SMS; claim before sending and review ambiguous deliveries without blind retries. Why: payment callbacks must not duplicate customer receipts.
- Saved Grow cards require explicit self consent and verified live card payment; keep raw tokens in provider vault, expose only display metadata and allow self revocation. Price changes enqueue service-only, idempotent issuer checks using server fees/caps. Why: no hidden mandates or reusable-token leaks.
