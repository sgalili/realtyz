# User credit management
- Use Super Admin-only exact-balance RPCs with per-account row locks, configured server conversion and audited ledger deltas; reject stale expected balances. Why: no role escalation, lost charges or unaudited funds.
- Users tables opt into Table scrollMode="page" with native sticky headers and the main surface owning both axes; other tables retain bounded scrolling. Why: uninterrupted page gestures without duplicate scroll owners.
- Aggregated import-history removal uses Super Admin-only record-key tombstones, never deleting operational jobs, accounts or inventory; links carry exact workspace/public identity and return state. Why: safe log deletion and scoped navigation.
- Imported-account first invitations require server uninvited/login checks; successful provider IDs arm one self-removing 48-hour reminder schedule. Token clicks/login cancel the protected follow-up queue; reminders are queued, not sent with unapproved Meta copy. Why: no premature reminders or unsolicited delivery.
- Invitation/history inventory uses database COUNT by developer_id; worker saved-row reads paginate, and both import screens invalidate invitation/history/developer/workspace queries per saved checkpoint. Why: accurate counts without row caps, zero-unit placeholders or stale cards.- Marketing companies live in their own Super Admin-only table; developers and projects link by id and change only through Super Admin RPCs. Why: one shared name list, safe moves between companies.
