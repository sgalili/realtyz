# User credit management
- Registry no-match persists per exact broker/license through a service-only fenced RPC and is excluded from batch inserts; outages remain retryable and no identity, gender or role is inferred. Why: stable gray state without weakening verification.
- Import repetition is a persisted job column, never a worker checkpoint flag; clean completion atomically queues one successor with its original configuration and remaining frontier. Why: mid-run toggles cannot overwrite progress or be lost to worker reports.
- Import property totals count saved workspace/source-matched listings, separately from the requested maximum; billing alerts require explicit provider balance evidence and a service-only per-recipient cooldown. Why: no invented counts, quota guesses or alert floods.
- Bulk registry rechecks snapshot the authorized fresh red waiting list into a server-owned serial leased queue; shared identity-save RPCs fence cancellation and stale licenses, event wakes plus active-only recovery survive logout, and UI reads persisted totals. Why: no borrowed identities, browser-dependent execution or late saves.
- Scanner countdowns anchor to meaningful server queue/deadline changes, never the ticking clock; promotion is audited, Super Admin-only and changes priority without altering creation dates or bypassing serial sends/quota. Why: real progress without false dispatch promises.
- HTML discovery results continue to the scanner server-side for both single and bulk jobs using the same saved source/creator, while paused lines and saved contacts block continuation. Why: leaving a card must not strand discovery or launch duplicate inquiries.
- Import status and history share useAdminImportJobs; count activity matches persisted workspace/source identity and enrichment completion, not aggregate history status. Why: one poll stream and a ring only on the item actually loading inventory.
- Import views remain mounted within the current authorized admin/tenant scope during section switches; session storage restores only UI selections/expansion, never data or privileges. Why: instant returns without retaining another tenant's results.
- Use Super Admin-only exact-balance RPCs with per-account row locks, configured server conversion and audited ledger deltas; reject stale expected balances. Why: no role escalation, lost charges or unaudited funds.
- Users tables opt into Table scrollMode="page" with native sticky headers and the main surface owning both axes; other tables retain bounded scrolling. Why: uninterrupted page gestures without duplicate scroll owners.
- Aggregated import-history removal uses Super Admin-only record-key tombstones, never deleting operational jobs, accounts or inventory; links carry exact workspace/public identity and return state. Why: safe log deletion and scoped navigation.
- Imported-account first invitations require server uninvited/login checks; successful provider IDs arm one self-removing 48-hour reminder schedule. Token clicks/login cancel the protected follow-up queue; reminders are queued, not sent with unapproved Meta copy. Why: no premature reminders or unsolicited delivery.
- Invitation/history inventory uses database COUNT by developer_id; worker saved-row reads paginate, and both import screens invalidate invitation/history/developer/workspace queries per saved checkpoint. Why: accurate counts without row caps, zero-unit placeholders or stale cards.- Marketing companies live in their own Super Admin-only table; developers and projects link by id and change only through Super Admin RPCs. Why: one shared name list, safe moves between companies.
- Marketing-company contacts (name/phone/gender) live on marketing_companies; when set, developer WhatsApp invitations go to the contact and the contact's phone becomes the account login phone (rejected if used elsewhere). Why: OTP reaches the person who manages the account.
- Invitation emails log exact subject/body/links in broker_invitation_emails (Super Admin read); send history expands rows from it. Why: auditable sent content.
- Send-history developer/marketing cards reuse MarketingContactLine (editable, with add prompts) fed by admin_marketing_contacts, show the developer logo as the card image and the recipient phone via the protected admin save action; status/date sit below the contact line. Why: one editable contact source without exposing data to non-Super Admins.
- Invitation attachments live in the private invitation-attachments bucket with a Super Admin-only invitation_attachments library; email sends them as Resend attachments, WhatsApp sends a signed-link document message after the template. Why: one reusable file list without public file exposure.
- Executive summaries are invitation_attachments rows with a unique summary_role (developer/marketing_company/broker/property_owner/affiliate); first-invitation dialogs preselect the recipient type's summary, and send history groups recipients server-side by user_roles (developer invites to a marketing contact count as marketing). Why: one file library, per-type defaults without a second store.
- Super Admin platform-mode switch lives in the system section (PlatformModeToggle). Why: one place to toggle marketplace mode.
- Broker outreach requires saved consent and OTP phone proof; the existing minute dispatcher claims ElevenLabs invitations once after the cancellation window. Why: durable scheduling without a second timer or duplicate calls.
- First contact (email and WhatsApp outreach) is a link-free opt-in naming the broker and their Yad2 address; login link and Rita voice follow only after a positive reply via the outreach journey. Why: anti-spam consent before any account link.

- Twilio and ElevenLabs management lives only in the Super Admin "voice" section (VoiceProvidersTab); credit/bonus pricing tools live in FinanceTab. Why: one privileged home for platform voice and pricing settings.
- Super Admin quick card charges go through grow-payments quick_charge to Grow's hosted checkout; TORAFF never collects card numbers, and paid quick_charge orders grant nothing. Why: PCI safety and no accidental entitlements.
- Broker Yad2 totals persist on admin_broker_onboarding.yad2_total_listings at account creation; cards/history show (imported/total) via src/lib/importRatio.ts and the My Properties add button reads only my_yad2_import_gap for the authorized workspace. Why: no NaN or cross-tenant counts.
- Blocked import jobs (provider 407/client_10020, or 429/504 cooldowns) are classified by src/lib/importJobBlock.ts and shown in an always-visible alert with Super Admin retry/dismiss via control_blocked_import_job. Why: a stuck 0/N job must never look like a normal wait.
