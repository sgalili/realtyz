# Public simulation safety
- Public demo uses the shared App routing with a role basename, AppLayout, AppSidebar and actual registered pages; never create a separate demo workspace shell. Why: identical controls, navigation and layout.
- PublicWorkspaceProvider supplies only presentation identity/roles and synthetic workspaces; real auth has no demo session, verified-role queries are disabled and the isolated QueryClient never contains real tenant data. Why: simulation is not authorization.
- publicWorkspaceTransport installs before descendants render and handles tables/RPC/functions locally; Auth, Storage, Realtime, remote fetch and localStorage are isolated or blocked with no passthrough. Restore is idempotent and persona switches remount providers/cache without signing out the real account. Why: no writes, credentials, provider activity or stale account data escape.
- Demo boot reads only the public platform setting through a captured anonymous transport, then passes it to the isolated data store; broker-only persona/workspaces and the shared route gate exclude marketplace pages before mounting. Why: mirror the current broker interface without reading real inventory or flashing partner views.
- Mutation denials and external publishing attempts show the shared read-only notice; sample signatures use the existing signing page and fake records only. Why: exploration remains usable without saves or provider activity.
