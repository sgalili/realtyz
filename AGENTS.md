# Architecture rules
- Wizard uses a fixed header/footer with only its body scrolling; amenities persist detailed features with legacy flags and scoped drafts; floor validation shares one helper. Why: visible actions and valid drafts.
- Header activity uses an anchored viewport-bounded dropdown with three primary tabs and compact credits; owned items render as a selectable list from the authorized My Ads RPC (batch share/campaign/delete), with content remounted on user/workspace changes. Intro outline art stays local and image sizing reserves space. Why: consistent cards, uncluttered mobile scrolling and no parallel tenant marketplace.
- The final intro slide uses separate grid tracks for text, Rita and its CTA, with height-aware compact spacing and typography. Why: keep all content within the viewport without internal scrolling or overlap.
- Desktop shell controls use the board's shared content width and account for its inner gutters; guest board header and search share the board container. Why: keep account, publication, page controls and property content on the same edges without resizing the current board.
- Homepage board uses a height-bounded flex layout with a non-scrolling header/search; in list view the property table card is the sole scroller and its column-header row stays pinned (separate borders, row separators on cells), in card view the page body scrolls; the authenticated shell disables its outer homepage scroll. Why: keep both control rows and the column headers stationary without duplicate scrolling or overlap.
- Campaign services reuse existing composers and shared action-pricing queries, configured units and precise credit formatting; post-network filters derive from unfiltered workspace feed cards and never connection flags. Why: consistent estimates and truthful independent filtering without tenant leakage.
- Signed-in home and legacy affiliate routes use the same public-safe feed; personal activity expands existing authorized management views without a second marketplace. Distribution tags read persisted publication/network flags and closing fields require server entitlement checks. Why: unified browsing without draft or commission leaks.
- Account self-deletion uses a service-only locked OTP/archive/purge RPC, excludes protected archives from cleanup and finalizes Auth deletion before reporting success; archive reads remain Super Admin RLS-only. Why: avoid races, erased references and false deletion success.
- Pre-post Facebook connection syncs confirmed memberships through the workspace-authorized cloud job path with cancellation and retry, never keyword search or optimistic membership. Why: preserve drafts and truthful tenant-scoped group state.
- Signup type and name are completed via authenticated constrained RPCs before protected content renders; existing names/identities and partner consent stay server-owned. Profile broker fields follow the active owner's broker identity or suspension, never partner membership. Why: prevent repeated selection, lost names and irrelevant verification without privilege escalation.
- Auth uses a viewport-bound shell, non-scrolling header/tabs and one native-scrolling form area with shared field styling; the unified company option maps to the existing developer signup flow without altering stored contractor roles. Why: stable geometry without empty signup gaps and preserved server-owned identity.
- Cloud monitoring mounts only for authenticated super_admin roles and its read-only endpoint rechecks user_roles server-side; queue counts resolve and authorize the active workspace, while Railway heartbeat and scheduler ticks remain separate. Why: prevent operational data leaks and false readiness.
- Wallet usage pricing is read-only and loaded from action_pricing on opening its hero dialog; reuse the admin query key without exposing editing controls. Why: display current configured costs consistently.
- Profile and office image uploads use the shared fixed-aspect crop dialog before storage; crop percentages map to original pixels and pending selections clear on workspace changes. Why: consistent image framing without premature uploads or tenant drift.
- Tours use authorized menus and stable state; never auto-mutate.
- Public ads use shared headings/publishers/public cache, never private profiles; container-width layouts. Fee notices require workflow context, never browsing. Why: relevance.
- Inventory and project campaign targets are workspace-scoped; authorize AI targets server-side, never store project refs in listing UUID fields. Why: isolation.
- Drafts retain user/workspace steps/errors; explicit publish, member defaults. Celebration owns canvas/audio.
- Publisher numbering excludes setup, preserves saved keys; resolved addresses reveal details; stale searches cannot overwrite selections.
- Publisher legal documents open in a nested view of the canonical Terms without unmounting the wizard; ready inventory and its count share a user/workspace-keyed paginated query and promotion readiness predicate. Why: exact return state and consistent counts without tenant drift or duplicate legal content.
- Publisher lead-price controls reuse shared bounds/colors and potential estimates; disabled fees hide settings without clearing limits/questions. Closing dual-mode callbacks persist both value and unit without changing legacy editors. Why: avoid unintended charges or fee conversions.
- Facebook auth/groups are mounted siblings, so Page state cannot interrupt groups/joining.
- Group membership UI reads persisted cloud events, never local membership overrides. Why: truthful status.
- Peer expansions use exclusive motion groups.
- Inquiry tiers need server-only workspace/listing identity and satisfactory screening; first turns/callbacks never qualify. Atomic upgrades charge only unpaid differences.
- Tables share sort/reorder/hide with visible grips and order-only reset; prefs never store listings. Native scrolling, no overlays. Why: consistency.
- My Ads stats use workspace-authorized RPCs; favorites are user-scoped, paginated and public-safe.
- Yad2 checks exact workspace records before daily claims; cache reads keep edits and source timestamps (no sliding freshness). Cache/scheduled feeds never invent/publish on failure. Search dispatch/results share sources; Homely needs verified workspace status. Counters use completed-search snapshots.
- Yad2 keeps original publisher snapshots, source buckets and scoped DOM evidence; never null-overwrites or classifies from related ads; license needs evidence.
- Group selection uses one checkbox per row, immutable deduplicated snapshots and no-op guards.
- Media dedup uses host/path hashes; Yad2 reuses validated own public cache, not other hosts. Why: safe reuse.
- Multi-select lists use the shared controls in src/components/ui/multi-select-controls.tsx so every page behaves the same.
- Partner rewards freeze into immutable listing_reward_snapshots on pick; charges use the snapshot. Trust scores are server-computed (compute_trust_score), super_admin-overridable, audited.
- Reward displays share bare configured-type indicators and the existing pricing dialog; table prices reuse partner net calculations and server closing entitlement. Public projections expose presence flags, with all closing amounts (including nested feature values) server-redacted. Submission fees and closing payouts resolve the workspace-matched immutable snapshot; public publication validates price and closing fee. Why: consistent guest-safe explanations and immutable committed rates.
- Listing lifecycle advances forward-only via advance_listing_stage; daily cron pauses partner distribution after 3 unanswered checks until confirm_listing_availability.
- Lead disputes, appeals and bans run only through audited security-definer RPCs; appeals need a neutral reviewer; bans freeze, never delete.
- Lead categories come from generated `leads.lead_category` (lead_kind → interest_tag → deal_type); filters, counts and badges read it. Why: legacy leads stored type only in interest_tag.
- Core labels use authorized owner roles; developer signup never grants broker roles. Clear queries/remount on tenant switch. Mode is account-scoped session state, never a role; consent stays RPC-only. Why: isolation.
- Wallet lock: credit_wallets trigger locks at balance<=0; ProtectedRoute sends locked non-superadmins to /wallet. Why: billing state lives in DB.
- payment_methods.provider_token is never client-granted; only provider backends insert cards.
- Personal links use auth RPCs; service attribution validates listing/workspace.
- Roles come only from user_roles; partner reads use server-redacted RPCs and verified-license guards.

- Closing splits: compute_closing_split pays 80% to authorized brokers (partner_can_view_closing) via idempotent paid_amount delta; otherwise platform retains 100%. No subscription plans; billing is credits only. Why: legal license model.
- Facebook groups UI is cloud-only; joins require server evidence and supplied answers/rule consent. Pool rebalancing and quotas are transactional and workspace-scoped. Why: truthful membership and isolation.
- Global instructions use global_ai_documents/private global-ai-training with Super Admin checks; global_ai_config is legacy only. Brains share BrainResources title-free text entry and derived filenames; global library comes first. Why: one library without tenant leaks.
- The shared advanced filter (LeadTypeFilterButton) resolves fields from server roles: partners get lead-first minimal sets, brokers the full set plus closing tier, developers/private market filters only; broker wins over affiliate. Why: each role sees only relevant filters.
- The public board feed (public-listings-board) admits only listings with a positive asking price, at least one configured reward and a non-generic publisher shown as "first name + last initial."; non-matching rows are filtered, never deleted. Why: no mock/dummy listings on the homepage while keeping data recoverable.
