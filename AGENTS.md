# Architecture rules
- IVR scopes voices/history and official WA sessions; measured duration drives configured-unit estimates. Serialized cached v3 demos use binary playback. Server-owned audio scripts learn style only after successful calls, keyed by sender/workspace. Why: prevent leaks, stale prices and unsent learning.
- Legal pages share LegalPageLayout and one bounded footer outside routes. Why: no overlap.
- Pricing edits target the authorized ad's saved workspace under RLS, never the unrelated active workspace. Only Super Admin manual edits bypass slider bounds; publication rules remain. Why: safe cross-workspace saves.
- Header activity uses an anchored viewport-bounded dropdown with three primary tabs and compact credits; owned items render as a selectable list from the authorized My Ads RPC (batch share/campaign/delete), with content remounted on user/workspace changes. Intro outline art stays local and image sizing reserves space. Why: consistent cards, uncluttered mobile scrolling and no parallel tenant marketplace.
- Final intro uses separate text/Rita/CTA tracks and height-aware sizing. Why: no scrolling or overlap.
- Desktop shell controls and the intro overlay use the board's shared content width and account for its inner gutters; guest board header and search share the board container. Why: keep intro, account, publication, page controls and property content on the same edges without resizing the current board.
- Listing-table views use a height-bounded flex chain with stationary controls and pinned table headings; the table alone owns both scroll axes and contains edge gestures. Public/app shells lock document scrolling and account for footer and sidebar bounds; card views retain internal results scrolling. Why: no double scrolling.
- Campaign creation mounts only its selected channel; services share precise configured credits. Network filters use unfiltered workspace feeds. Partner property pickers reuse paginated public-safe inventory with partner availability/closing-audience predicates, never private rows. Why: focused setup and isolated inventory.
- Signed-in home and legacy affiliate routes use the same public-safe feed; personal activity expands existing authorized management views without a second marketplace. Distribution tags read persisted publication/network flags and closing fields require server entitlement checks; commission edits by a Super Admin on ads they do not own default to read-only with a header-pencil unlock (super_admin SELECT on listings). Why: unified browsing without draft or commission leaks.
- Self-deletion uses locked service-only OTP/archive/purge. Bulk deletion shares one users table and exact-ID endpoint, verifies server roles, protects self/Super Admin, removes owned files via service-only lookup/Storage API, then purges and deletes Auth before success. Archives stay protected. Why: safe deletion.
- Graph Page selection uses server discovery/bindings; confirmed cloud groups stay separate with bounded cancellable scans. Reject client passwords/cookies. Server-redact social identity; append service-only durable retry-keyed rotating footers after sanitization, never in drafts. Why: private publishing.
- Signup uses auth-bound RPCs, separate type/details and city menus; server validates owner deals, preserves identities/consent and never auto-imports developer links. Bonuses are one-time server grants, Super Admin-configured and read back in welcome. Why: safe completion without duplicate grants.
- Auth uses server OTP and auth.uid signup RPCs, never a bypass; company maps to developer. PersonalLanguage reads auth user's profiles.gender, not workspace/metadata; recipient copy shares explicit gender variants, never guessing names or editing approved text. Why: isolation.
- Cloud monitoring mounts only for authenticated super_admin roles and its read-only endpoint rechecks user_roles server-side; queue counts resolve and authorize the active workspace, while Railway heartbeat and scheduler ticks remain separate. Why: prevent operational data leaks and false readiness.
- Wallet usage pricing is read-only and loaded from action_pricing on opening its hero dialog; reuse the admin query key without exposing editing controls. Why: display current configured costs consistently.
- Profiles use shared crops/cities, clear pending uploads on workspace switches and reread saved completion. Upgrade checks displayed owner, submits only as self. Personal tasks skip lead/calendar access and scope all CRUD/drafts by user+workspace. Why: isolation.
- Future calls use workspace-authorized meetings RPCs and the existing tour-reminder tick, with atomic per-call claims and purpose-specific approved official WhatsApp templates; never create a second permanent timer. Why: tenant-safe scheduling without duplicate sends or unauthorized free-text reminders.
- Public grid/details use safe publishers with server-gated PropertyCommissionIcons inside BrokerAttribution; image actions share favorites. Fee notices stay contextual. Why: owner identity and pricing privacy.
- Property headings fit one address/price row; maps use photo markers, safe DOM popups and details-only selection with scroll-to-top. Why: avoid overlap and premature navigation.
- Campaign targets use authorized rows or public-view facts, override unrelated drafts and discard stale responses; project refs stay out of UUID fields. Why: exact, isolated actions.
- Drafts retain scoped errors and post-only exclusions, never deleting source photos. Explicit publish; celebration owns canvas/audio. Cached reward sounds follow account-only new ledger earnings, never workspace balances or historical grants.
- Publisher numbering excludes setup; preserves keys and resolved addresses; ignores stale searches.
- Publisher legal documents open in a nested view of the canonical Terms without unmounting the wizard; ready inventory and its count share a user/workspace-keyed paginated query and promotion readiness predicate. Why: exact return state, consistent counts.
- Public publisher pricing and shared card-header rules: read src/components/public/AGENTS.md.
- Facebook auth/groups are mounted siblings, so Page state never interrupts groups.
- Group membership UI reads persisted cloud events, never local membership overrides. Why: truthful status.
- Inquiry tiers need server-only workspace/listing identity and satisfactory screening; first turns/callbacks never qualify. Atomic upgrades charge only unpaid differences.
- Tables share sort/reorder/hide; rewards never sort. HorizontalTableScroll owns both axes and movable wheel axes (RTL Shift-wheel too), preserves nested scrolling, collapses nested owners. Homepage stays bounded; prefs never store listings. Post-animation reveal scrolls only the table, anchoring property summaries below headings. Why: no hidden summaries.
- Every successful app sign-in and completed signup lands on the global homepage; the layout only clears old pending login flags and never chooses a dashboard. OAuth authorization consent remains a separate flow. Why: all account types browse the same public-safe feed without bypassing role completion.
- My Ads stats use workspace-authorized RPCs; favorites are user-scoped, paginated and public-safe, served only by src/hooks/useListingFavorites.ts so hearts and the owner menu share one list. Why: one favorite state.
- Yad2 checks exact workspace records before daily claims; cache reads keep edits and source timestamps (no sliding freshness). Cache/scheduled feeds never invent/publish on failure. Search dispatch/results share sources; Homely needs verified workspace status. Counters use completed-search snapshots.
- Yad2 keeps original publisher snapshots, source buckets and scoped DOM evidence; never null-overwrites or classifies from related ads; license needs evidence.
- Group selection: one checkbox per row, immutable deduped snapshots, no-op guards; peer expansions use exclusive motion groups.
- Media dedup uses host/path hashes; Yad2 reuses validated own public cache, not other hosts. Why: safe reuse.
- Multi-select lists use the shared controls in src/components/ui/multi-select-controls.tsx so every page behaves the same.
- Partner rewards freeze into immutable listing_reward_snapshots on pick; charges use the snapshot. Trust scores are server-computed (compute_trust_score), super_admin-overridable, audited.
- Reward displays share ordered indicators and the existing pricing dialog; zero states use explicit public reward flags or authorized numeric values, never missing/redacted amounts. Table prices reuse partner net calculations and server closing entitlement. Public projections expose presence flags, with all closing amounts (including nested feature values) server-redacted. Submission fees and closing payouts resolve the workspace-matched immutable snapshot; public publication validates price and closing fee. Closing reward color uses the shared `.closing-level-*` classes (`closingLevelClass`/`closingRewardLevel` mirror the server level); an icon keeps that color while its non-price hint stays gray. Why: guest-safe, immutable rates.
- Listing lifecycle advances forward-only via advance_listing_stage; daily cron pauses partner distribution after 3 unanswered checks until confirm_listing_availability.
- Lead disputes, appeals and bans run only through audited security-definer RPCs; appeals need a neutral reviewer; bans freeze, never delete.
- Lead categories come from generated `leads.lead_category` (lead_kind → interest_tag → deal_type); filters, counts and badges read it. Why: legacy leads stored type only in interest_tag.
- Core labels use authorized owner roles; developer signup never grants broker roles. Clear queries/remount on tenant switch. Mode is account-scoped session state, never a role; consent stays RPC-only. Why: isolation.
- Wallet lock: credit_wallets trigger locks at balance<=0; ProtectedRoute sends locked non-superadmins to /wallet. Why: billing state lives in DB.
- payment_methods.provider_token is never client-granted; only provider backends insert cards.
- Personal links use auth RPCs; service attribution validates listing/workspace.
- Roles come only from user_roles; partner reads use server-redacted RPCs and verified-license guards.
