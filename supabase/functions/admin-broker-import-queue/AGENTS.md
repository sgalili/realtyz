# Broker import queue
- Live chunks process one listing with a twelve-second post-request gap; 429 pauses for at least five minutes unless a Super Admin explicitly resets the cooldown through the locked control RPC. Reset leaves work paused, preserves checkpoints/cache and records the actor/time; only manual resume restarts work. Why: controlled override without automatic retries or stale worker saves.
- Web Unlocker REST calls omit sticky session/IP settings and use provider-managed rotation with bounded peer/request diagnostics; Browser fallback reconnects per fetch. Why: supported API semantics without pretending IP uniqueness or 429 prevention is guaranteed.
- Provider requests allow 120s inside a 130s scrape budget and 140s worker-call timeout; structured failure logs redact credentials and bound payloads, and retry uses persisted checkpoints/cache. Why: avoid premature aborts while returning before the platform deadline.
- Discovery uses the existing Yad2 Bright Data parser with a leased Super Admin job, compact source records and individual detail enrichment; public/search reads retain their existing cache gates. Why: reuse exact-source attribution without broad scraping privileges.
- Database-triggered steps persist per-broker/per-listing checkpoints, atomically lease and control jobs, and stop between external actions; pause never cancels an already submitted save. Why: modal-independent progress and safe resume.
- Only current Super Admin-created accounts without first login may be reused; all ads are active-checked unpublished drafts and missing identity is never invented. Why: prevent account takeover and false publication.
- Registry checks require exact license and person match; any fallback approval is tied to job, administrator, user and license and remains distinct from official verification. Why: prevent borrowed broker identities.- Search pages and ad details are read through the service-only scrape cache with fixed TTLs measured from fetch time (never extended on read); empty/failed fetches are never cached, and live-status checks and imports always go live. Why: avoid repeat Bright Data spend without stale activity or publication.
- Imported brokers are grouped by license; a hidden Yad2 mobile creates the account as pending_contact with a .invalid placeholder email, completed only through Super Admin admin-broker-contact (pre-first-login, uniqueness-checked) before any invitation. Why: import without inventing identity or contacting anyone automatically.
