# Facebook extension rules
- FB group-post engagement is scraped read-only by the extension (ext-metrics + pairing-token RPCs); counters only increase and roll up into the campaign card.
- fb_user_groups.is_blocked needs manual unblock: confirmed rejection blocks immediately; pending approval is not rejection. Group connection/discovery UI is cloud-only with no extension installation controls. Cloud joins use supplied answers and explicit rule consent; only confirmed membership becomes ready. Cloud posts run server-side quota/rotation preflight in both dispatch paths.
- Page sync uses the workspace's own binding. Server routing rejects foreign workspace/Page payloads and never prunes partial scrapes; scrape tabs close only after app receipt ACK persists.
- Extension presence is verified live: any extension-only action (group search/join/sync/pair) must pass ensureExtensionReady (RZ_EXT_STATUS ping) before running; a stale passive install flag is cleared and the UI shows the install/manual fallback instead of a dead-end error. Detection lives only in src/lib/extensionDetect.ts — never re-implement it.
