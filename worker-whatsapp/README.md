# Worker עצמאי לגילוי WhatsApp למתווכים

## מה קיים ומה לא
התור נפרד לגמרי מ־`broker_import_jobs`. המספר נשמר ב־`broker_whatsapp_contacts` ולא ב־`profiles.phone` או בטלפון הכניסה.
מתווך נבחר בכרטיס Super Admin; השרת בוחר מודעת יד2 שכבר שמורה בבעלות ובמרחב של אותו מתווך.
ה־Worker קורא את הדף דרך Bright Data והענן מחלץ רק קישור WhatsApp מפורש ויחיד באזור `main`, כולל אזור הקשר הראשי של המשרד (`forsale-agency-contact-section`) בתוך ה־aside הצף שנצפה במקור יד2. יתר אזורי הצד/המלצות ותוכן מוסתר מוחרגים. מספר טלפון רגיל או שדה phone ב־JSON אינם הוכחה ל־WhatsApp. תגובת result ולוג הענן כוללים סיבת חילוץ ומספר מועמדים, ללא המספר עצמו.

**לא מבוצעת שליחה מכפתור יד2 ולא נעקפות הגנות יד2.** Web Unlocker מחזיר HTML ואינו לקוח WhatsApp. אם הפעולה קיימת רק אחרי JavaScript/לחיצה או שקישור קצר מסתיר את המספר, המשימה תחזור `not_found`. יש לאמת את מבנה המקור החי לפני הרחבת החילוץ; אין להמציא מספרים.

**גילוי בלבד:** אין ב־Worker פעולת שליחה. כפתור WhatsApp בכרטיס Super Admin פותח בנפרד את חלון ההזמנה הידנית הקיים, דרך מספר Meta הרשמי בלבד, עם אישור הסכמה ותבנית מאושרת. לא נפתח צ׳אט ממספר אישי ולא נשלחה הודעה במהלך ההתקנה.

## Railway
צרו **שירות חדש** מהמאגר, Root Directory: `/worker-whatsapp`, Start Command: `npm start`, מופע אחד, Node 22 ומעלה. אין צורך ב־Build Command, Domain או HTTP healthcheck. **לא לשנות את שירות האתר או את `/worker`.**

משתנים:
- `TORAFF_BROKER_WA_API_URL`: כתובת פונקציית `broker-whatsapp-worker` מהגדרות הענן; מסתיימת ב־`/functions/v1/broker-whatsapp-worker`.
- `BROKER_WA_WORKER_SHARED_SECRET`: ערך זהה בסודות Cloud וב־Railway, לפחות 32 תווים; אינו הסוד של Worker הייבוא.
- `BRIGHT_DATA_API_KEY` או `BRIGHTDATA_API_TOKEN`: החיבור הקיים של Bright Data; שני השמות נתמכים, והערך נשאר סודי ב־Railway.
- `BRIGHTDATA_UNLOCKER_ZONE`: Zone פעיל התומך Web Unlocker. מומלץ Zone/מכסת קצב ייעודיים כדי שהשירותים לא יתחרו על אותה מכסה.
- `BROKER_WA_WORKER_ENABLED=true`: רק אחרי הגדרה ובדיקת חיבור; עשוי להפעיל משימות שאושרו.
- `BROKER_WA_CONCURRENCY`: ברירת מחדל 1, בין 1 ל־3.
- `BROKER_WA_REQUEST_INTERVAL_MS`: ברירת מחדל 5000, בין 1000 ל־60000; השהיה משותפת לכל ערוצי שירות זה.
- `BROKER_WA_POLL_INTERVAL_MS`: ברירת מחדל 10000, בין 1000 ל־60000.
- `BROKER_WA_SOURCE_TIMEOUT_MS`: ברירת מחדל 45000, בין 10000 ל־60000.
- `BROKER_WA_WORKER_ID`: מזהה מופע ייחודי, עד 100 תווים.

לא להוסיף מפתח service-role, כתובת מסד או סיסמת מסד. רק הענן פונה ל־Meta ומחזיק בהרשאות שמירה.

## תקלות וקצב
`SKIP LOCKED` ונעילה ל־120 שניות מונעים שני עובדים לאותה משימה. עד שלושה ניסיונות גילוי; 429 מכבד Retry-After עד 180 שניות. timeout ושגיאה נשמרים בענן. השעיית ספק מפסיקה את השירות בלי לולאת ניסיונות. הרשאת Super Admin ומצב דמו נבדקים גם בזמן ביצוע ושמירה.
העובד מחדש את הנעילה כל 25 שניות בזמן קריאה/שמירה. בקשות status/enqueue/claim מפעילות התאוששות: pending ללא התקדמות של עובד בתור במשך 180 שניות נסגר כ־failed; running עם נעילה שפגה מוחזר ל־retry עד שלושה ניסיונות. תור מרוכז נשמר כל עוד יש התקדמות/heartbeat; המתנת Retry-After תקינה אינה נקטעת. אין תהליך גילוי פעיל בלי עובד Railway רץ; ההתאוששות משחררת חסימה אך אינה מתקינה אותו.
הכפתור המרוכז מוסיף במנות של 20 רק חשבונות מתווכים מיובאים ללא מספר WhatsApp, ומדלג על דמו/יזמים/חברות שיווק/מקור חסר. מספר טלפון רגיל שנמצא בקישור tel יחיד נשמר כהצעה במשימה; שינוי טלפון הכניסה דורש שמירה ידנית נפרדת. WhatsApp ידני אינו משנה את טלפון הכניסה, וגילוי אינו דורס מספר ידני אחר.
לכל איתור מרוכז יש `broker_whatsapp_batches` נפרד בבעלות המנהל שהתחיל אותו. הכפתור נשאר זמין לעצירה גם בזמן הוספת משימות וגם בזמן קריאת המקורות; העצירה מבטלת רק משימות פעילות באותה פעולה וחוסמת הוספות/תוצאות מאוחרות באמצעות נעילות. המספרים שכבר נשמרו נשארים. קריאת מקור שכבר יצאה ל־Bright Data יכולה להסתיים, אך תוצאה אחרי ביטול אינה נשמרת.
גודל payload נבדק לאחר קידוד JSON; מקור גדול מדי נסגר כשגיאה מפורשת בלי לולאת retry. שינוי זה דורש פריסת קוד שירות `/worker-whatsapp`; יתר תיקוני החילוץ והעצירה רצים בענן.
אין פעולת שליחה אוטומטית ואין טיימר Cloud נוסף. שדות הפנייה שהוגדרו בתחילת העבודה הושארו כמסומנים לא־בשימוש ונחסמו בשכבת השמירה; ה־Worker אינו משתמש בהם.

הקצב כאן אינו מכסה גלובלית לשני השירותים: אם משתמשים באותו חשבון Bright Data, יש לתקצב יחד את קצבי הייבוא והגילוי. כשל השירות הזה אינו עוצר את תור הייבוא, אך חסימת חשבון ספק משותף יכולה להשפיע על שניהם.

בדיקות מקומיות: `npm test`. פריסה וחילוץ/מסירה חיים דורשים בדיקה נפרדת; בדיקות מדומות אינן הוכחת פעילות מול יד2/Meta.
## קו סריקה ייעודי (Green API)
כבוי כברירת מחדל. להפעלה ב־Railway: `BROKER_WA_SCANNER_ENABLED=true`, `TORAFF_BROKER_WA_SCANNER_API_URL` (פונקציית `broker-whatsapp-scanner`) ו־`BROKER_WA_SCANNER_WORKER_SECRET` (זהה לסוד בענן, שונה מסוד הגילוי). ה־Worker רק קורא מודעות ומעיר את הענן כל 30 שניות; המכסה, ההשהיה האקראית, שעות הפעילות והעצירה נאכפים בענן. ב־Green API של קו הסריקה בלבד: Webhook URL = `.../functions/v1/broker-whatsapp-scanner-webhook`, Webhook URL Token = `Bearer <GREEN_SCANNER_WEBHOOK_TOKEN>`, והפעלת incomingWebhook ו־stateWebhook.
